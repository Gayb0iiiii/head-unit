# Production head-unit UI acceptance plan

Working brief, 2026-10-24. The production UI runs as an Orange Pi system shell. The aesthetic is quiet Apple-like glass with large touch targets, a coastal palette, and no vehicle branding. It must make Home useful without LIVI or internet. The sidebar destinations, in order, are Radio, Bluetooth, CarPlay, Settings, Apps; Home remains one touch away. No simulated state enters production.

Design reference: [Apple CarPlay](https://developer.apple.com/design/human-interface-guidelines/carplay), [materials](https://developer.apple.com/design/human-interface-guidelines/materials), [layout](https://developer.apple.com/design/human-interface-guidelines/layout), and [accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility). This is a custom Linux shell inspired by the guidance, not certified CarPlay UI. Glass is restrained on the navigation rail and controls; content uses stable, readable surfaces. The selected primary display is the [Lilliput TK1560](https://www.lilliputdirect.com/products/tk1560?variant=54752775504211), 15.6-inch 1920×1080 landscape touch, about 141 pixels per inch. Design and visual review prioritize that profile while smaller viewports remain supported. Its actual EDID, USB touch mapping, brightness behavior, input latency and day/night appearance still need physical review. Pixel widths measured in Chromium are not physical touch-target certification.

## Layout and visual language

- Palette: deep water `#102738`, slate `#365c70`, sea glass `#90c5ce`, frost `#dcebed`, and warm daylight `#eef4ed`. Day and night both need legible surfaces, with wallpaper visible through glass rather than text opacity.
- Type: a single system sans family, with large clock and source information, clear 16–20 px navigation labels, and a small number of quiet secondary labels. No all-caps dashboard copy or developer explanations on Home.
- Home on the TK1560: a large clock and date sit over a dark wallpaper scrim, with a compact weather status beneath. Observed media occupies one appropriately sized stable surface beside it. Three icon-led source launchers sit below, and one short connection status follows. The composition uses balanced wallpaper space without stretching absent data into giant panels. At 800×480, the hierarchy compresses into two columns and removes shortcuts already in the sidebar.
- The five sidebar destinations stay visible in the requested order. The selected route has a clear marker. Home is a separate primary control. At narrow portrait sizes the destinations become a reachable bottom strip.
- Settings groups local appearance controls first; device and diagnostic controls live below or in clearly labeled secondary sections. Unsupported services do not get fake controls.

## Behavior and truth

| Area | Acceptance |
| --- | --- |
| Home | One local clock, observed media only, weather/temperature empty state when no approved source exists; no duplicate clock or giant blank region. |
| Phone link | An initial offline state differs from a connection lost after success. Home stays navigable. A compact status communicates absence without dominating the screen. |
| Radio | Digital, AM and FM have a coherent destination, but no station, scan, tuner frequency, or playback success is invented. |
| Bluetooth | Distinct from CarPlay. No pairing or connected-device claim without a real service. |
| CarPlay | A destination exists; it does not claim connection or rendered video without the native engine. |
| Apps | Clear app navigation without fabricated installed apps or a dead tile. |
| Settings | Day/night, bundled or selected local wallpaper, UI scale, glass, dock, and Debug overlay persist, remain usable offline, and have visible focus/pressed states. |
| Debug overlay | Off by default. UI frame callback cadence, aggregate CPU, used/total RAM, active default-route interface rates, and bounded TCP-connect latency to Google are labeled accurately; GPU use is unavailable absent a verified counter. Timers and in-flight network probing stop when disabled/unloaded. |
| Weather | No geolocation or network request before location/provider consent. A future source needs a timestamp, stale policy, and cancellable bounded requests. |
| Directions | No panel until an authoritative, validated native turn-by-turn feed is present; video is not parsed for directions. |
| Desktop | Settings shows a capability-gated switch. It remains disabled until a separate desktop session, seat handoff provider and return launcher have been verified; head-unit stays boot default. |

## Local acceptance matrix

Review screenshots and browser interactions first at the selected 1920×1080 landscape profile, then 1280×720, 1024×600, 800×480, and 480×800 in both appearance modes. For each size, check Home, every sidebar destination, Settings, keyboard focus, scroll reachability, minimum touch targets, no horizontal overflow, and visual balance at 90%, 100% and 115% UI scale. With a keyboard and mouse, Tab/Shift+Tab must expose visible focus, Enter/Space must activate controls, Escape must back out of a local destination, and click/wheel access must work without hover-only controls or a hidden cursor. At 800×480 and 115%, offline Home should fit the viewport without losing the clock, media status, source navigation or dock; the debug readout must not cover any of them. Settings may scroll deliberately. Exercise route changes repeatedly, reload after saving preferences, initial offline and reconnect transitions, a rejected action, and overlay enable/disable/unload. Run the repository tests, build, and socket fixture afterward. Browser tests with a sandbox bypass are visual and behavioral evidence only; they cannot establish Electron sandbox security. Actual Pi display, touch, clock timezone, native media, and boot behavior require later hardware acceptance.

## Cloud visual and interaction review, 2026-10-24

The user-supplied Pi photo transfer is currently blocked by the Library download service; do not mark that image as visually inspected. The reported defects were reproduced from the prior UI in a local Chromium screenshot pass. The revised production build was actually rendered and visually reviewed at all five viewport sizes above, including 1920×1080 and 800×480 Home, Apps, Settings, Radio, Bluetooth and CarPlay, a portrait Home, and day appearance. Selected screenshots are in `evidence/ui-baseline-*.png`; these filenames refer to the disconnected fixture, not a hardware baseline. The fixture supplies only an offline host view and does not invent media, weather, sensors or phone data.

An automated Chromium interaction pass visited each of the six destinations twice at each viewport **before the later wallpaper/scale/metrics changes**. It checked visible headings, page errors, horizontal overflow, and dock targets at least 48 CSS pixels in both dimensions. At 800×480 it also checked day and wallpaper persistence after reload, Debug overlay on/off and reload, Apps reordering/reset/persistence, and a collapsed settings group surviving a setting change. A separate connected fixture checked observed media, pause routing, stale cleanup, visible keyboard focus and reduced motion. The pass first exposed a browser-only `Illegal invocation` from the default clock timer binding; the connected fixture exposed the same issue in media-expiry scheduling. Both were fixed and covered by regressions. At that checkpoint the full Node suite reported **432 passing tests**; the static production build and the real local Unix-socket fixture passed. The earlier browser was launched with its sandbox disabled only because this cloud Chromium sandbox helper is unavailable; none of that setting enters the product launcher. These checks do not prove Electron sandbox enforcement, GPU performance, physical touch readability, native LIVI, radio, Bluetooth, weather, or boot behavior.

The repeatable browser passes are `python3 tests/ui-production.py` and `python3 tests/ui-connected.py` after `npm run build`, with Python Playwright and Chromium installed. They default to Chromium's sandbox. This saved cloud environment required `HEADUNIT_TEST_CHROMIUM_NO_SANDBOX=1` for those **test processes only** because its Chromium sandbox helper is unavailable. This flag must not be used in the Electron launcher or Pi setup. The connected test uses explicitly named fixture phone/media data and does not establish a real connection.

Remaining product dependencies: no live radio tuner or Bluetooth pairing/audio adapter is integrated; no weather provider/location has been approved; no validated LIVI turn-by-turn metadata feed exists. The selected TK1560's EDID, touch mapping and effective UI scale need verification on hardware. The Home clock uses the Pi's local timezone, which needs checking on hardware. These destinations communicate unavailable state rather than successful operation.

The Desktop control and staged LXQt/Xorg installation and return plan are in [desktop-session-handoff.md](desktop-session-handoff.md). No desktop provider has been installed, so the control is disabled rather than exiting to tty. Ubuntu resolute ARM64 package candidates and total installation footprint must be checked on the Pi before approval.

## Pending review after the visual checkpoint

Custom wallpaper imports are local-only and restricted to PNG, JPEG or WebP under 1 MiB, decoded dimensions of 320×240 to 4096×4096 and at most 12 megapixels. The validated data URL is stored locally; failed storage leaves only the current-session image and a visible save notice. Reset removes the stored image. UI scale is 90–115% in 5% steps, with the native projection plane excluded to preserve picture geometry. A separate sandboxed browser review of commit `fb1d8ca` confirmed wallpaper import/reset and scale persistence, and exposed oversized offline Home cards, 800×480 scroll at 115%, debug readout overlap, small rail symbols, and unbalanced Settings. Local commits `938a0e3` and `d8ed50a` address these findings; their final rendered proportions **remain pending independent review**. No new Pi pixel pass or product sandbox setting change occurred.

The production content panels now use stable 94% dark or 96% light surfaces over the wallpaper; reduced-transparency mode uses solid surfaces. A numeric WCAG contrast test composites each surface over black, white, bright yellow, cyan and magenta wallpaper colors. The lowest tested secondary-text ratios are **12.02:1 at night** and **6.50:1 by day**, above 4.5:1. This is a token-level compositing bound, not a measured physical display or a full pixel/text-size audit. The navigation rail, all icon states and the imported-image reflow still need rendered review.

## Personalisation review candidate

Settings opens a dedicated offline wallpaper gallery with 19 local choices in Landscapes, Pastels, Solid colours and Gradients. Meadow and Blue Forms are original small SVG compositions inspired by nostalgic desktop scenery; they are not official Windows images. The gallery also retains the validated local PNG, JPEG or WebP upload. A live gallery preview follows the selected wallpaper and tuning. Six named accents and separate brightness (60–140%), dimming (0–60%) and blur (0–8 px) controls use validated steps, persist locally and have a single adjustment reset. Resetting adjustments keeps the selected wallpaper and imported image. The gallery has large tile buttons, keyboard focus and Escape back navigation; appearance changes remain locked when the host reports motion. No location, network or native backend is involved.

The wallpaper effect is confined to the background layer. Home cards and other content surfaces keep their opacity. A day-mode light plaque protects headings and the small Home status on dark wallpapers; night mode keeps its dark upper/lower scrim over pale wallpapers. Browser review must confirm actual contrast and reflow at the extreme pairs: day + Ink, night + Ivory, brightness 140% / dim 0%, and brightness 60% / dim 60%, at 1920×1080 and 800×480. It must inspect each SVG's rendered pixels, gallery tile labels, focus and selected state, sliders and reset, imported image removal, persistence after reload and non-overlap with the Debug overlay. The local Node/build checks do not certify those rendered outcomes or Pi GPU performance. Import remains limited to a 1 MiB image; the bundled vectors are under 2 KiB each.

This candidate passed **436 Node tests**, the static build, the local Unix-socket fixture, SVG XML parsing and Python browser-test syntax. The sandboxed browser pass could not launch in the saved cloud environment: `/usr/lib/chromium/chrome-sandbox` is not configured as a root-owned mode-4755 helper. No browser sandbox or product sandbox setting was changed. The rendered checks above await an independent sandboxed browser and actual Pi review.

The debug overlay shows total CPU non-idle share between `/proc/stat` samples; RAM used is `MemTotal − MemAvailable`; network arrows are byte-rate deltas for the lowest-metric active default-route interface, excluding loopback. Route switches and counter resets produce unavailable rates until a new pair of samples. “Google TCP latency” is a TCP connect to `google.com:443`, including DNS, at most every 10 seconds with a 1.5-second deadline; it is not ICMP ping. It runs only while the overlay asks for samples and an in-flight probe is cancelled when the overlay stops. GPU use remains unavailable: Linux 6.18 Panthor's optional per-client job-time fdinfo is not a reliable whole-device busy-time percentage, and enabling profiling would change a kernel setting. Mesa/Panthor acceleration was observed in the prior Pi graphics log, separately from this metric. Do not substitute GPU frequency or per-client job durations for a global percentage.

The landscape Home composition after `85c1c5b` has not yet had a secure rendered review. The browser regression now checks full-HD clock/date containment at 90/100/115%, media and weather proportions, icon-led launcher sizes, source position, keyboard navigation, and compact 800×480 scale/overlay behavior. Node and build checks cannot establish these pixel outcomes.
